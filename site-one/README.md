# Массовая выгрузка 61–65

Система обработки строк для серверов 61–65 с ролевой моделью, статистикой, журналом действий и хранением данных в MariaDB/MySQL. phpMyAdmin используется как закрытый интерфейс к базе.

## Права

- `user` — закреплён за сервером 61, 62, 63, 64 или 65; видит рабочие листы и статистику только своего сервера; admin-панели нет;
- `admin` — видит все серверы, создаёт, меняет и удаляет обычных пользователей;
- `superadmin` — видит все серверы и управляет `admin` и обычными пользователями;
- `developer` — высший уровень, видит все серверы и может создавать, менять и удалять пользователей любой роли, включая других `developer`.

Собственный активный аккаунт нельзя удалить или изменить через панель — это защита от случайной потери доступа.

## Рабочие листы

Для каждого сервера доступны: «Обмен дом на дом», «Авто на Авто», `/pay`, «Уникальная», «Уровень 3,4,5», «Работы», «Маркетплейс», «Трейды» и отдельная «Статистика».

Статусы строк:

- ожидание;
- есть нарушение;
- нет нарушений;
- требуется помощь руководства — строка сразу попадает в очередь admin-панели;
- ранее отработано.

Импорт файлов будет добавлен следующим этапом. Структура БД и интерфейс уже готовы принимать строки в таблицу `work_rows`.

## Запуск через Docker

1. Скопируйте `.env.example` в `.env`.
2. Замените все значения паролей длинными уникальными секретами.
3. Запустите:

```powershell
docker compose up --build -d
```

- сайт: `http://localhost:3000`;
- phpMyAdmin: `http://localhost:8080`;
- сервер базы в phpMyAdmin: `database`;
- логин и пароль phpMyAdmin: `DB_USER` и `DB_PASSWORD` из `.env`.

Первоначальные `superadmin` и `developer` создаются из переменных `BOOTSTRAP_*` только при отсутствии соответствующей роли в базе. Пароли пользователей хранятся как `scrypt`-хеши.

Для production используйте `*_PASSWORD_HASH`, включите `COOKIE_SECURE=true`, поставьте приложение за HTTPS reverse proxy и не публикуйте MariaDB/phpMyAdmin напрямую в интернет.
